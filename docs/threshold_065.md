# Threshold 0.65 전체 원본 평가 — 2026-11-25

[Root](../readme.md) · [GUI](../src/GUI/readme.md) · [검증 기록](verification.md)

Genuine·Impostor 기본 Threshold를 모두 **0.5 → 0.65**로 변경했습니다. 기존 전체 원본 평가의 점수로 판정을 다시 계산한 결과, 전체 18,960쌍의 **FMR은 100% → 0.185185%, FNMR은 0% → 0%**입니다. EER와 점수 자체는 같습니다.

## 평가 조건

- 기본 production weight 4개(`fvc2000_db3.bin`, `fvc2002_db3.bin`, `fvc2004_db1.bin`, `combined.bin`)를 사용합니다. 현재 파일의 SHA-256을 기존 평가 기록과 대조했습니다.
- FVC2000 DB3_B·FVC2002 DB3_B·FVC2004 DB1_B의 원본 각 80장, 총 240장을 사용합니다. 추가 노이즈·증강은 없습니다.
- 모든 원본을 등록용·인식용으로 사용하고 양방향 전체 쌍을 비교합니다. 자기 자신·동일 pixel 비교는 제외합니다. DB별 Genuine 560쌍·Impostor 5,760쌍이며, 서로 다른 DB 사이의 비교는 없습니다.
- DB 조합은 해당 DB 내부의 점수를 합쳐 공통 Threshold로 지표를 다시 계산합니다. DB별 EER의 단순 평균이 아닙니다.
- 공개 점수는 DB 전용·combined 점수의 최솟값을 소수 셋째 자리로 반올림한 값입니다. `score >= 0.65`이면 수락합니다.
- **새 추론·시간 측정은 하지 않았습니다.** 2026-11-24의 native C++ Core 결과·Template·측정 시간을 재사용해 현재 C++ Engine·보고서 코드로 재판정했습니다. 실제 Windows DLL·Worker·IPC 실행 결과는 아닙니다.

## 해석

현재 점수의 범위는 `(clamp(cosine, 0, 1) + 1) / 2`에 따라 0.5–1.0입니다. 초기값 0.5에서는 정상 반환한 타인 점수도 모두 수락했습니다. 0.65로 높이면 현재 원본 집합에서 본인 거절 없이 타인 오인식을 줄입니다.

전체에서 남은 타인 오인식은 32쌍입니다(FVC2002 16쌍·FVC2004 16쌍, 양방향 기준). 모든 본인 1,680쌍은 수락했습니다. Threshold 변경으로 모델의 점수 분리 능력이나 EER가 좋아졌다는 뜻은 아닙니다.

이 값은 현재 원본 집합을 보고 정한 시작값입니다. 새로운 DB·노이즈 이미지·다른 팀 DLL에 대한 최적값이나 독립 Test 성능을 보장하지 않습니다. Results의 수동 Threshold 조절을 유지하며, DLL을 새로 Load하면 두 값을 0.65로 초기화합니다. 0.65는 KISA가 정한 고정 Threshold가 아닙니다.
